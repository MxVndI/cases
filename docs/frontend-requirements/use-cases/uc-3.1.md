# UC-3.1: Открытие кейса

**Эпик:** [Epic 3: Открытие кейсов](../epics/epic-03-case-opening.md)

## Описание

Процесс одиночного открытия кейса авторизованным пользователем на странице `/cases/$caseId` с получением случайного предмета.

## Акторы

- **Основной:** Пользователь
- **Вторичный:** Cases Service (API), Payment Service (проверка и списание баланса)

## Предусловия

- Пользователь авторизован.
- Пользователь находится на странице `/cases/$caseId`.
- На балансе достаточно CHC для открытия.

## Основной сценарий

1. Пользователь нажимает кнопку «Открыть кейс».
2. Система отправляет запрос `POST /cases/{id}/open` к Cases Service.
3. Cases Service проверяет баланс через Payment Service и списывает стоимость кейса.
4. Cases Service случайным образом определяет выигрышный предмет и возвращает результат.
5. Система генерирует рил из 60 слотов, размещая выигрышный предмет в заданной позиции.
6. Система запускает анимацию прокрутки рулетки (5 секунд, cubic-bezier easing).
7. Рулетка останавливается на выигрышном предмете.
8. Система отображает полноэкранный оверлей с результатом и эффектом частиц (particles).
9. Пользователь выбирает:
   - «Забрать» (Take) — предмет добавляется в инвентарь, оверлей закрывается.
   - «Продать» (Sell) — система показывает 2-шаговое подтверждение продажи.
10. При подтверждении продажи: система вызывает `casesApi.sellItem`, предмет конвертируется в CHC.
11. Оверлей закрывается, баланс в хедере обновляется, пользователь может открыть кейс снова.

## Постусловия

- Баланс уменьшен на стоимость кейса.
- Предмет либо добавлен в инвентарь, либо конвертирован в CHC.
- Открытие записано в историю.

## Альтернативные потоки

- **2a.** Недостаточно средств — кнопка неактивна, открытие невозможно. Система предлагает пополнить баланс.
- **6a.** Пользователь нажимает «Пропустить» — анимация мгновенно завершается, сразу отображается результат.
- **9a.** Пользователь нажимает «Отмена» при 2-шаговом подтверждении продажи — возвращается к выбору Забрать/Продать.
