# UC-4.1: Продажа предмета

**Эпик:** [Epic 4: Инвентарь и баланс](../epics/epic-04-inventory-balance.md)

## Описание

Процесс конвертации предметов из инвентаря или результата открытия кейса в CHC (CaseHubCoin). Поддерживается индивидуальная продажа и массовая продажа всех предметов.

## Акторы

- **Основной:** Пользователь
- **Вторичный:** Cases Service (API), Payment Service

## Предусловия

- Пользователь авторизован.
- В инвентаре есть хотя бы один предмет, или пользователь находится на экране результата открытия кейса.

## Основной сценарий (продажа из инвентаря — отдельный предмет)

1. Пользователь открывает инвентарь (вкладка «Инвентарь» в профиле `/profile`).
2. Пользователь нажимает кнопку «Продать» на карточке предмета.
3. Система отображает 2-шаговое подтверждение: первый клик переводит кнопку в состояние «Подтвердить?», второй клик — подтверждает.
4. Пользователь подтверждает продажу (второй клик).
5. Система вызывает `casesApi.sellItem` с идентификатором предмета.
6. Cases Service удаляет предмет из инвентаря и зачисляет стоимость на баланс через Payment Service.
7. Карточка предмета исчезает с анимацией.
8. Суммарная стоимость инвентаря и баланс в хедере пересчитываются.

## Основной сценарий (массовая продажа — Sell All)

1. Пользователь нажимает кнопку «Продать всё» в инвентаре.
2. Система отображает 2-шаговое подтверждение с указанием общей суммы.
3. Пользователь подтверждает.
4. Система вызывает `casesApi.sellAll`.
5. Cases Service удаляет все предметы из инвентаря и зачисляет общую стоимость на баланс.
6. Инвентарь очищается, баланс обновляется.

## Основной сценарий (продажа из результата открытия)

1. После открытия кейса (UC-3.1 / UC-3.2) на экране результата пользователь нажимает «Продать» на предмете.
2. Система отображает 2-шаговое подтверждение.
3. Пользователь подтверждает продажу.
4. Система вызывает `casesApi.sellItem`.
5. Предмет конвертируется в CHC, баланс обновляется.

## Постусловия

- Проданные предметы удалены из инвентаря.
- Баланс увеличен на стоимость проданных предметов (CHC).

## Альтернативные потоки

- **3a.** Пользователь не подтверждает (не нажимает второй раз в течение таймаута) — кнопка возвращается в исходное состояние, предмет остаётся.
- **5a.** Ошибка сервера — система отображает уведомление об ошибке, предмет остаётся в инвентаре.
