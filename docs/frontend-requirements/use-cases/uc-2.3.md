# UC-2.3: Авторизация через OAuth

**Эпик:** [Epic 2: Регистрация и авторизация](../epics/epic-02-auth.md)

## Описание

Процесс входа или регистрации через внешний OAuth-провайдер: Discord или Яндекс. При первом входе аккаунт создаётся автоматически. Сессия устанавливается через cookie.

## Акторы

- **Основной:** Гость
- **Вторичные:** OAuth-провайдер (Discord / Яндекс), Auth Service (API)

## Предусловия

- Гость находится на странице авторизации `/login` или регистрации `/register`.
- У гостя есть аккаунт Discord или Яндекс.

## Основной сценарий

1. Гость нажимает кнопку «Войти через Discord» или «Войти через Яндекс».
2. Система выполняет редирект на страницу авторизации выбранного OAuth-провайдера.
3. Гость вводит учётные данные провайдера и подтверждает доступ для CaseHub.
4. Провайдер выполняет callback-редирект обратно на CaseHub с авторизационным кодом.
5. Auth Service обменивает код на токен провайдера, получает данные профиля.
6. Auth Service создаёт или находит существующий аккаунт и устанавливает cookie-сессию.
7. Система перенаправляет пользователя на главную страницу `/`.
8. Хедер обновляется: отображаются баланс и меню пользователя.

## Постусловия

- Пользователь авторизован.
- Установлена cookie-сессия.
- При первом входе создан новый аккаунт с данными из профиля провайдера.

## Альтернативные потоки

- **3a.** Гость отклоняет запрос на доступ — провайдер перенаправляет обратно, система возвращает на страницу авторизации CaseHub.
- **5a.** Ошибка обмена кода на токен — система отображает сообщение об ошибке OAuth.
- **6a.** Аккаунт, привязанный к провайдеру, заблокирован — система сообщает о блокировке.
