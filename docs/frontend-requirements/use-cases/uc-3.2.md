# UC-3.2: Мульти-открытие кейса

**Эпик:** [Epic 3: Открытие кейсов](../epics/epic-03-case-opening.md)

## Описание

Процесс одновременного открытия нескольких экземпляров одного кейса (x3 или x5) на странице `/cases/$caseId`.

## Акторы

- **Основной:** Пользователь
- **Вторичный:** Cases Service (API), Payment Service (проверка и списание баланса)

## Предусловия

- Пользователь авторизован.
- Пользователь находится на странице `/cases/$caseId`.
- На балансе достаточно CHC для нескольких открытий (цена × количество).

## Основной сценарий

1. Пользователь нажимает кнопку «x3» или «x5» на странице кейса.
2. Система проверяет баланс (стоимость × количество).
3. Система отправляет несколько запросов `POST /cases/{id}/open` к Cases Service (по одному на каждое открытие).
4. Cases Service проверяет и списывает баланс через Payment Service для каждого открытия.
5. Cases Service возвращает выигрышные предметы для каждого открытия.
6. Система отображает экран результатов в виде сетки со всеми выпавшими предметами.
7. Пользователь может для каждого предмета индивидуально:
   - «Забрать» (Take) — предмет добавляется в инвентарь.
   - «Продать» (Sell) — 2-шаговое подтверждение, затем `casesApi.sellItem`, предмет конвертируется в CHC.

## Постусловия

- Баланс уменьшен на суммарную стоимость (цена × количество).
- Каждый предмет обработан индивидуально (инвентарь или продажа).
- Все открытия записаны в историю.

## Альтернативные потоки

- **2a.** Недостаточно средств для выбранного количества — кнопка неактивна.
- **3a.** Частичная ошибка — если один из запросов вернул ошибку, остальные результаты всё равно отображаются.
