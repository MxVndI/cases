# B-UC-3.2: Открытие кейса пользователем

**Эпик:** [Epic B3: Управление кейсами](../epics/epic-b03-cases.md)

## Описание

Открытие кейса пользователем

## Акторы

- **Первичный:** Пользователь
- **Система:** Case Service, Auth Service

## Предусловия

Пользователь авторизован (cookie `sid` установлен), выбрал кейс для открытия

## Основной сценарий (текущая реализация)

1. Фронтенд отправляет `GET /api/cases/open/{id}` с cookie `sid`
2. Case Service передаёт `sid` в Auth Service через HTTP (`GET /verify_user/{ssid}?token=...`)
3. Auth Service подтверждает сессию и возвращает UID пользователя
4. Case Service возвращает UID авторизованного пользователя

## Планируемые шаги (в разработке)

5. Case Service загружает кейс и его предметы с вероятностями
6. Проверяется баланс >= цена кейса (через Payment Service)
7. Генерируется случайный предмет на основе взвешенных вероятностей
8. Списывается стоимость кейса с баланса (атомарная операция)
9. Предмет добавляется в инвентарь пользователя
10. Открытие записывается в историю
11. Запись добавляется в recently_opened (Redis list)
12. Возвращается выпавший предмет

## Постусловия (текущие)

Возвращён UID пользователя; полная игровая логика в разработке

## Постусловия (после завершения)

Баланс уменьшен, предмет в инвентаре, запись в истории

## Альтернативные сценарии

1. Недостаточно средств → 400
2. Кейс не найден → 404
3. Кейс пуст (нет предметов) → 400
4. Сессия невалидна → 401/403
