# B-UC-1.2: Авторизация по email

**Эпик:** [Epic B1: Аутентификация и авторизация](../epics/epic-b01-auth.md)

## Описание

Авторизация по email через одноразовый код. Паролей нет — пользователь получает 6-символьный код (shortuuid) на email и вводит его для подтверждения.

## Акторы

- **Первичный:** Гость
- **Система:** Auth Service, User Service

## Предусловия

- Гость находится на странице входа по email
- SMTP-сервер доступен

## Основной сценарий

### Шаг 1 — Запрос кода

1. Гость вводит email и нажимает «Войти»
2. Фронтенд отправляет `POST /email/login/start` с телом `{email}`
3. Auth Service генерирует UUID (`cvid`) и 6-символьный код (`shortuuid`)
4. Код сохраняется в Redis с ключом `cvid:{uuid}`, TTL 10 минут
5. Auth Service отправляет код на email через SMTP (`MailSender`)
6. Устанавливаются cookies: `email` и `cvid`
7. Возвращается ответ — фронтенд перенаправляет на форму ввода кода

### Шаг 2 — Подтверждение кода

8. Гость вводит полученный код и нажимает «Подтвердить»
9. Фронтенд отправляет `POST /email/login/finish` с телом `{email, code}`
10. Auth Service считывает `cvid` из cookie, получает код из Redis по ключу `cvid:{cvid}`
11. При совпадении кода:
    - Публикуется RPC-запрос в Redis Streams (`user.rpc`) для получения/создания пользователя по email
    - Создаётся сессия в MongoDB, кешируется в Redis
    - Session ID подписывается (HMAC-SHA256), устанавливается cookie `sid` (30 дней)
    - Возвращаются данные пользователя

## Постусловия

- Пользователь авторизован
- Cookie `sid` установлен (HMAC-SHA256, TTL 30 дней)
- Сессия сохранена в MongoDB и Redis
- Пользователь создан в User Service (если первый вход)

## Альтернативные сценарии

1. **Неверный код** → перенаправление на `/auth-error`
2. **Истёк TTL кода** (10 мин) → ключ удалён из Redis, ошибка валидации
3. **Ошибка отправки email** → 500
4. **User Service недоступен** (таймаут RPC) → сессия создаётся без данных пользователя
