# B-UC-2.3: Публичный профиль и управление статусом

**Эпик:** [Epic B2: Управление пользователями](../epics/epic-b02-user.md)

## Акторы
- Гость / Пользователь (публичный профиль)
- Сервис (межсервисные вызовы с Bearer-токеном)

## Предусловия
- Для публичного профиля: никнейм пользователя известен
- Для межсервисных вызовов: Bearer-токен из списка разрешённых

## Основной сценарий: Публичный профиль

1. Клиент отправляет `GET /v1/users/public/{nickname}`
2. Система ищет пользователя по никнейму
3. Система возвращает публичные данные: id, nickname, role, status (без email)

## Альтернативный сценарий: Управление статусом

1. Admin Service отправляет `PATCH /v1/users/{user_id}/status` с Bearer-токеном
2. Система проверяет токен (из settings.allowed_tokens)
3. Система обновляет статус пользователя (active → blocked или blocked → active)
4. Система возвращает обновлённый профиль

## Исключения
- Пользователь не найден → 404
- Невалидный или отсутствующий Bearer-токен → 401/403

## Постусловия
- Публичный профиль возвращён без приватных данных
- Статус пользователя обновлён в MongoDB
