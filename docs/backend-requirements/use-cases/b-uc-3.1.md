# B-UC-3.1: Создание кейса администратором

**Эпик:** [Epic B3: Управление кейсами](../epics/epic-b03-cases.md)

## Описание

Создание кейса администратором

## Акторы

- **Первичный:** Администратор
- **Система:** Case Service

## Предусловия

Администратор авторизован и открыл панель управления кейсами

## Основной сценарий

1. Администратор заполняет форму: название, цена, предметы с вероятностями
2. Фронтенд отправляет `POST /api/admin/cases` через Admin Service (BFF)
3. Admin Service добавляет `token` из локального конфига и проксирует запрос к `POST /cases/` Cases Service
4. Cases Service проверяет `token` в `allowed_tokens`
5. Cases Service валидирует данные (цена `>= 100`, `drop_chance` каждого предмета в `[0, 1]`)
6. Создаётся документ `Case` в MongoDB с полем `case_content: list[CaseContent]`
7. Возвращается UUID созданного кейса

## Постусловия

Кейс создан и доступен через `GET /cases/`

## Альтернативные сценарии

1. Невалидные данные → 422 (Unprocessable Entity)
2. Неверный токен → 403
3. Предметов в `case_content` нет → создаётся пустой кейс (нет проверки на непустоту)
