# B-UC-5.2: Проксирование CRUD и загрузка изображений

**Эпик:** [Epic B5: Администрирование (BFF)](../epics/epic-b05-admin.md)

## Акторы
- Администратор

## Предусловия
- Администратор авторизован (cookie `sid`, роль admin подтверждена через require_admin)

## Основной сценарий: Проксирование CRUD

1. Администратор отправляет запрос на `/admin/cases/` (или `/admin/items/`, `/admin/rarities/` и т.д.)
2. Dependency `require_admin` проверяет cookie sid → Auth Service → User Service (роль admin)
3. Admin Service формирует запрос к Cases Service с межсервисным токеном
4. Cases Service выполняет операцию и возвращает результат
5. Admin Service проксирует ответ администратору

## Альтернативный сценарий: Загрузка изображения

1. Администратор отправляет `POST /admin/upload/image` с файлом (multipart/form-data)
2. Система проверяет тип файла (png/jpeg/webp/gif) и размер (≤ 5 МБ)
3. StorageService загружает файл в RustFS (S3-совместимое хранилище) через boto3
4. Система возвращает `{url: "<public_url>"}` для использования в предметах и кейсах

## Исключения
- Недопустимый тип файла → 400
- Файл слишком большой → 400
- Не admin → 401/403

## Постусловия
- CRUD-операция выполнена в Cases Service
- Изображение загружено в S3, URL доступен для использования
