# B-UC-3.3: SSE-лента и история выигрышей

**Эпик:** [Epic B3: Управление кейсами и справочниками](../epics/epic-b03-cases.md)

## Акторы
- Гость / Пользователь (SSE-лента, публичная история)
- Авторизованный пользователь (личная история)

## Предусловия
- SSE-лента: Redis pub/sub канал `wins_channel` активен
- Личная история: пользователь авторизован (cookie `sid`)

## Основной сценарий: SSE-лента

1. Клиент подключается к `GET /cases/wins/stream`
2. Система подписывается на Redis pub/sub канал `wins_channel`
3. При каждом новом выигрыше система отправляет `data: {...}\n\n`
4. Каждые 15 секунд отправляется keepalive (`: keepalive\n\n`)
5. Соединение поддерживается до отключения клиента

## Альтернативный сценарий: Последние выигрыши

1. Клиент запрашивает `GET /cases/recent_wins?limit=20`
2. Система читает из Redis List `recent_wins` (LRANGE)
3. Для каждого выигрыша обогащает данные: `item_img_url` (из Item), `user_nickname` (из User Service)
4. Возвращает список выигрышей

## Альтернативный сценарий: Личная история

1. Авторизованный пользователь запрашивает `GET /cases/wins/my?limit=50&offset=0`
2. Система верифицирует сессию через Auth Service
3. Система запрашивает WinHistory из MongoDB (сортировка по timestamp desc)
4. Возвращает список выигрышей с пагинацией

## Постусловия
- Клиент получает данные о выигрышах в реальном времени или по запросу
