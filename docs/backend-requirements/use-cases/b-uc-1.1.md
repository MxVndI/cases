# B-UC-1.1: Авторизация через OAuth

**Эпик:** [Epic B1: Аутентификация и авторизация](../epics/epic-b01-auth.md)

## Описание

Авторизация через OAuth

## Акторы

- **Первичный:** Гость
- **Система:** Auth Service

## Предусловия

Гость находится на странице входа

## Основной сценарий

1. Гость нажимает кнопку OAuth-провайдера (Discord/Яндекс)
2. Фронтенд перенаправляет на GET /{provider}/login
3. Auth Service формирует URL авторизации через fastapi-sso
4. Гость перенаправляется на страницу провайдера
5. Провайдер авторизует пользователя и возвращает на callback URL
6. Auth Service получает данные пользователя через GET /auth/{provider}/callback
7. Auth Service запрашивает User Service через Redis Streams (user.rpc): получить/создать пользователя по email
8. Auth Service создаёт сессию в MongoDB с данными пользователя
9. Auth Service кеширует сессию в Redis
10. Auth Service подписывает session ID (HMAC-SHA256) и устанавливает cookie sid
11. Пользователь перенаправляется на /welcome

## Постусловия

Пользователь авторизован, cookie sid установлен, сессия в MongoDB и Redis

## Альтернативные сценарии

1. Провайдер отклоняет авторизацию → перенаправление на /auth-error
2. User Service недоступен (таймаут RPC) → сессия создаётся без данных пользователя
